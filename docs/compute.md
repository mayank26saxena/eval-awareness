# Compute

## Hardware requirements (bf16 weights)

| Model | Weights | Hardware |
|---|---|---|
| Qwen2.5-0.5B / Qwen3-4B / Qwen2.5-7B | 1 / 8 / 15 GB | Apple Silicon with ≥24 GB unified memory (MPS), or any ≥24 GB GPU |
| Gemma-3-12B | 24 GB | ≥40 GB GPU |
| Gemma-3-27B | 54 GB | 1× 80 GB GPU (H100 / A100) |
| Llama-3.3-70B | 140 GB | 2× 80 GB GPUs, or remote access through [NDIF](https://ndif.us) |

`scripts/common.py` selects `mps`, `cuda` or `cpu` automatically.

## Setup on a GPU machine

```bash
git clone https://github.com/<owner>/eval-awareness.git && cd eval-awareness
pip install uv && uv venv --python 3.12 && uv pip install -r pyproject.toml
hf auth login     # required for gated models (Gemma, Llama); accept the model license on Hugging Face first
```

## Running a model

`scripts/run_pipeline.sh` runs generation, judging, probing and transfer for one model and dataset. On macOS each step runs under `caffeinate -ims`, so long runs are not interrupted by idle sleep:

```bash
scripts/run_pipeline.sh Qwen/Qwen2.5-7B-Instruct v3_main                 # all steps
scripts/run_pipeline.sh Qwen/Qwen2.5-7B-Instruct v3_main probe transfer  # selected steps
```

The individual steps can also be run directly:

```bash
M=google/gemma-3-27b-it
python scripts/generate.py --model $M --data data/rendered/v2_main.jsonl
python scripts/generate.py --model $M --data data/rendered/v2_single.jsonl
python scripts/judge.py results/gemma-3-27b-it/responses_v2_main.jsonl --data data/rendered/v2_main.jsonl
python scripts/probe.py --model $M --data data/rendered/v2_main.jsonl
python scripts/probe_transfer.py --model $M
```

Approximate cost on a single 80 GB GPU: 2–3 GPU-hours per model for generation, judging and probing on the v2 dataset.

## Reproducibility notes
- **Batch size.** Generation defaults to batch size 1 with greedy decoding. On MPS, batched greedy decoding produced different outputs for identical prompts depending on batch composition. Larger batches are faster on CUDA, but keep batch size 1 for results that are comparable across machines.
- **Activation caches.** `results/<model>/activations_*.npz` are excluded from version control and regenerated by `probe.py`. For 27B they are about 1–2 GB.

## NLA inference
The NLA activation verbalizer (AV) is a second model of the same size as the target. On a single 80 GB GPU:
1. Cache target-model activations at the NLA layer. `probe.py` already stores all layers.
2. Unload the target model.
3. Serve the AV with SGLang following [`kitft/natural_language_autoencoders`](https://github.com/kitft/natural_language_autoencoders) (`docs/inference.md`). Load the scaling and prompt parameters from each checkpoint's `nla_meta.yaml`.
