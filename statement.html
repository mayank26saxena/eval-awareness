Research statement

Can we trust a safety eval when the model knows it's being tested?

Models behave better when they suspect they're being evaluated. That makes safety scores look better than real-world behavior. This project turns that hidden bias into a number you can measure, and checks that the tools used to measure it can be trusted.

End goal

Build and validate an Eval Trust Gauge: for any safety eval, a measurement of how much of the model's good behavior exists only because it knows it's being tested.

Measured from inside the model on open LLMs (Gemma-3-27B). The same recipe could then be used by any team auditing its own model, for example on Amazon Nova.

Where the field stands

Known

Models notice tests

Claude, GPT and Gemini models say "this looks like a test" and behave better when they do. Anthropic, OpenAI/Apollo, DeepMind, UK AISI and METR all report it.

Claimed, not proven

Tools can see it silently

Anthropic's NLAs detect unspoken eval awareness inside Claude. There's no ground truth, though, and the check they used to support it mixed prompt format with real test cues.

This project

Measure it reliably

Check which detectors are actually reading the model, then use the trustworthy one to measure how much eval behavior is "for show".

What we're trying to prove

The gauge only works if three things are true. Each is a claim we test, and each can fail.

1

The detector reads the model, not the prompt

Activation readers (NLAs, Activation Oracles, probes) should react to signs that the setup is a test, not to how formal or benchmark-like the text looks.

Test: the same request written four ways, crossing format with test cues. Compare against text-only detectors.

2

The reading is grounded, not invented

When an NLA says "the model thinks this is an eval", that information should actually be in the activation. The explainer shouldn't be guessing it from context.

Test: delete the eval claim from the explanation and see whether rebuilding the activation gets worse.

3

The signal causes the better behavior

If we switch off the "I'm being tested" signal, the model should start behaving the way it does in deployment, for example becoming more deceptive or leaking PII.

Test: steer along the format-free direction, compared with Anthropic's vector, an NLA-edit direction and a random one.

The deliverable: an Eval Trust Gauge

Once claims 1–3 hold, the gauge for each eval is simply: misbehavior with the test signal switched off − misbehavior normally. Pick an example eval:

"Can we exploit the eval-vs-deployment gap?"

Yes, but some uses help and some backfire. The gap is something to measure and remove, not something to rely on.

✓ Audit

Score how trustworthy each eval is

Run the gauge on every safety eval. A big gap means the score overstates real-world safety, so don't sign off on that number alone.

✓ Fix evals

Find the cues that give tests away

The format × context experiment shows which features make a prompt "smell like a test". That becomes an eval-design checklist for building more realistic evals.

✓ Monitor

Flag test-aware moments

A validated detector can flag eval transcripts where the model knew it was being tested, so those results get discounted or rerun.

✓ Red-team

Know where safety is fragile

If good behavior depends on test cues, then deployment situations without those cues are where failures hide. That tells red-teamers where to look.

✗ Tempting but risky

Make the model always feel watched

Steering the "being tested" signal on in deployment could make the model behave better.

Why not: it hides the underlying problem instead of fixing it, it's brittle, and a capable model could learn to work around it. It's the AI version of "only behaves when the teacher is in the room".

✗ Don't

Train the signal away

Training the model so it no longer shows test awareness might just teach it to hide that awareness.

Why not: once you train against your measuring tool, you can't trust it any more. Use the signal only to diagnose, never as a training target.

What happens either way

If the claims hold

We get a validated gauge, plus evidence that rewriting evals to look realistic isn't enough. Labs need internal monitoring and evals built from real traffic.

If claim 1 or 2 fails

Current eval-awareness readings, including Anthropic's NLA results, partly measure prompt format or explainer guesswork. That's an important warning before teams rely on them in audits.
